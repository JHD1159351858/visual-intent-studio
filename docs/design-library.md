# 本地整页设计与组件实现库

设计库包含 6 个整页范例和 20 个组件原生适配，保存为本地 HTML/CSS/JavaScript 资料，用于给 Demo 生成提供明确的分区、视觉参数、交互和实现参考。六类页面分别面向聊天助手、知识问答、写作工具、数据分析、分步报告和智能体门户。它会读取 `data/design-pages.json` 与 `data/design-components.json`；临时测试目录未提供这些文件时返回空库。

页面资产位于 `design-library/pages/`，组件资产位于 `design-library/components/`，预览位于 `design-library/previews/`。接口先从元数据中的真实 ID 查找条目，再读取声明的资产路径。JSON、字段、重复 ID、跨目录路径和通过链接逃逸的文件会拒绝读取。

整页选择先判断用途，再匹配最近一次用户明确点名的标题、ID 或别名。未匹配到用途时不强加整页。局部修改依据已有方案，仅保留配方规则和已确认或已使用的组件参考；原页面 HTML 继续作为修改基础。未确认的范例属于设计建议，不替代已确认需求。

每轮最多使用一个完整页面和三个组件实现，包含元数据与代码的完整 JSON 参考输入最多 30000 字符。已确认或已有方案的组件优先于整页范例，超过预算的实现整块跳过，不截断 CSS、JavaScript 或 HTML。组件只有在其真实来源条目符合当前 `ready` 条件、来源 URL 一致且作用层符合已确认选择时才会加入。组件资料保留参数、兼容性、冲突、移动端行为和减少动态规则。

玻璃卡片的内部材质属于 `surface`，动态描边属于 `border`，外侧光晕属于 `outer-glow`。局部要求只修改边缘时，提示词必须保留玻璃内部、内容与布局；每个来源条目分别记录原生适配边界。这些实现是本项目的原生参考适配，不能包装成已集成原作者组件或已经接通真实智能体服务。

运行本地导出：

```powershell
npx.cmd tsx scripts/export-design-knowledge.ts
```

脚本确认页面和组件资产可读取后，仅生成 `docs/coze-knowledge/05-整页设计范例.txt`、`06-高频组件实现.txt` 与独立的 `design-library-manifest.json`。它保留原有 01–04 文件及 `manifest.json`。新增 TXT 使用 `---CASE---` 分段，包含真实来源、结构与参数、适配限制及完整代码所在本地路径。

导出不会自动上传或绑定 Coze。云端不能读取本地 HTML 或预览路径；如需使用云端持久知识库，应将新增 TXT 实际导入、核对处理结果并绑定发布。TXT 的代码路径是资料定位，应用生成时才由本地后端把完整实现加入本轮上下文。浏览器验收、来源视频验证和真实智能体调用是分别需要证据的事项。
