# 跨学科页面提示词生成流程实施计划

**目标：** 用户一次输入，DeepSeek 在服务端依次完成整页设计规划、按需案例检索、具体实施要求编写、独立文字审查与最多一次修订。仍交付开发提示词，不执行页面代码或宣称视觉验收。

**架构：** 在现有 `generateDesignPrompt` 中编排新规划/审查模块，沿用现有 DeepSeek 传输、只读参考工具、来源校验和选材去重。规划每请求一次，重复组合重选完成后审查最终稿；仅审查通过才写成功历史。Coze/兼容接口保持现有行为。

**约束：** 保留已确认对象、作用层、功能与用户最新需求；不固定学科模板、配色或动效数量；不发送全库；不暴露思考或规划/审查原始 JSON；流式编写稿标记待审查；新增模型调用共用整个请求十分钟上限。失败不静默降级为成功。

- [x] 新增 `shared/design-planning.ts` 与 `server/design-planning.ts`：结构化设计方案、素材获取/质量/回退要求、机制检索词；独立审查返回通过或带原文证据的修改项。验证：合法方案、无效协议、代码内容、伪造审查证据与取消测试。
- [x] 修改 `server/design-prompt.ts`、`server/design-prompt-instructions.ts` 与结果类型：规划进入检索编写上下文，保留原来源闸门、组合重选；最多一次修订后复审；最终标记 `renderedPageVerified: false`。验证：调用顺序、已读引用、确认项保护、审查失败/取消不写历史、其他 provider 不增加调用。
- [x] 扩充独立集成测试并适配现有 DeepSeek 网络夹具，运行相关测试后完整测试和 Next 构建。修改只围绕上述流程，不触碰地理 Demo。
- [x] 使用真实配置对多个不同学科需求执行模型实测，保存方案、工具调用摘要、最终提示词及审查结果；凭据与模型思考不写报告。只验证提示词流程与学科差异，不称为页面美观验收。

验收：同一需求不重新填写即可走完四步；不同学科形成不同主题主体和构图；库引用真实且已读；审查不通过不保存成功稿；中断能终止后续步骤；现有刷新恢复、选材与导出协议兼容。

已执行：534 项单元/接口测试、Next 生产构建、standalone SSE全流程与取消、350视频Range、1440/390浏览器验收通过。真实模型的不同学科实测进行中；早期失败用于修正通用规划格式纠正、服务端需求快照、复审范围，保留失败证据，不放宽来源闸门。

最终：543项测试通过；真实模型经迭代分批完成五学科，来源均已读；成功样本与早期失败保存在 artifacts/design-workflow-evaluation/acceptance-report.md。没有渲染新页面，不把文字审查等同视觉验收。
