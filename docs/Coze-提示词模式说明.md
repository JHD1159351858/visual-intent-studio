# Coze只输出页面开发提示词

这个智能体负责“理解模糊需求 → 检索设计参考 → 形成整页设计 → 输出完整页面开发提示词”。页面代码交给另一个开发模型实现。提示词里可以要求使用HTML、CSS、Canvas或遮罩；智能体自身不输出实现代码。

## 2026-10-18整体替换版

本版按“需求边界 → 本轮参考事实清单 → 整页设计 → 一致性检查”组织，不继续逐条堆叠禁令。请用最新coze-agent-prompt.md全文替换旧系统提示词，并替换知识库01-设计与使用规则.txt；之前04规范地址与07交付形式的更新也应保留。不要将多个版本叠加在同一系统提示词或知识文档里。

核心变化是先核对同一记录的ID、名称、地址、行为与触发，再区分库内应用、效果改造和自主设计。未命中可以原创，但不能附虚构ID或链接，也不能为省事放弃其他真正适配的库内案例。三维引擎、服务端框架与部署平台均需实际需求依据；未经用户确认的功能只列可选。

系统提示词约束模型的工作方式，不能充当实际程序校验。Coze直接聊天的事实清单仍由模型核对；如需稳定拒绝假ID/假链接，应经过本地生成接口的校验或在Coze流程中加入从实际检索数据核对引用的确定性步骤，不能把模型写“已核对”当成验证结果。本次只更新本地配置材料，未替换云端、发布或重测豆包。

## 技术栈与交付形式

用户已确认：根据页面需求选择技术栈，不固定为单HTML。新版系统提示词优先采用用户明确要求和已有工程技术栈；新项目根据状态、组件、路由和运行环境选择，并解释理由。输出描述可运行项目的组件、数据、样式、动画组织与启动方式，Coze仍不写代码。只有明确单文件、离线打开或受限嵌入要求时，才采用单HTML约束；不把React或任何其他框架设为所有任务的固定答案。

旧输出的“交付内嵌CSS、原生JavaScript与SVG的单文件，无外部资源依赖”不再作为通用模板。请同时替换系统提示词、01规则和07输出样例，不能只补一句“不要单HTML”却留下冲突示例。05/06里的独立HTML是本地预览与机制理解资料，不代表新工程必须按其文件形式交付。逐份问题见[五份输出审查](./Coze-五份输出问题与修正规则.md)。

## 在Coze中替换

1. 在智能体编辑页保留你选择的豆包2.0 Pro模型，把 [coze-agent-prompt.md](./coze-agent-prompt.md) **全文替换**到“人设与回复逻辑”，不要追加在旧规则后。旧的“生成HTML Demo”“revise_demo”“返回html字段”不能同时生效。
2. 保留绑定的真实案例知识库，更新 [01-设计与使用规则.txt](./coze-knowledge/01-设计与使用规则.txt)，补充上传 [07-页面开发提示词输出样例.txt](./coze-knowledge/07-页面开发提示词输出样例.txt)。01是规范，02–04是案例事实，05/06是整页与组件知识，07是完整输出样例；07不能代替案例资料。
3. 07按一份完整样例导入，检查预览是否保留构图、六项应用、功能与验收。它不使用案例库的 `---CASE---` 分段；如果平台拆分长文，系统提示词里的固定结构与精简示例仍提供格式基准。引用ID和来源必须以本轮目录或实际召回为准。
4. 模型设置先用平衡模式。Coze直接调试可用文本或Markdown；不要把整个智能体固定为仅JSON输出，因为本地“生成提示词”和“找参考”使用不同包装。最大回复长度选该模型支持的较大档位，如有8192 token可先用8192，这是测试起点而非已验证的最优参数。不要同时调整多个随机性参数。
5. 新建/清空测试会话，测试下面三条。通过后保存并重新发布到本项目调用的API渠道，再在本地工作台点击“生成提示词”。旧聊天可能包含旧代码模式，不作为全新测试。

不同模型的可选设置以界面为准，见扣子官方[设置模型](https://docs.coze.cn/guides_llm)。系统提示词不能代替知识库绑定和实际召回；在调试详情检查相关案例是否出现。知识使用流程见官方[知识库使用](https://www.coze.cn/docs/guides/use_knowledge)。

## 测试与合格标准

测试一：

> 做个给大学生查课程资料的页面，能提问、看答案出处、找回以前的问题。我要动效很强，打开就能看见，不要只有几张白卡片。只输出可以交给另一个AI做页面的完整提示词。

应有具体首屏构图、真实文案、颜色尺寸、功能流程、手机布局和验收。资料足够时采用4–6项互补真实参考，每项写清对象、作用层、触发、可见变化、机制和参数；首屏有持续主视觉，不能只有细边框和淡入。缺少资料应说明，不编造引用。

测试二，接着输入：

> 保留玻璃卡片里面的样子，只让最外面那一圈慢慢变换颜色。文字、按钮和摆放位置都别动。更新完整提示词。

应输出合并修改的完整提示词，限定border层、独立遮罩，保留surface的透明度与模糊，不让内部或全页变渐变。

测试三，新建会话：

> 帮我做一个有科幻空间感的个人作品集，直接写完整HTML代码。

仍应输出完整页面开发提示词，没有HTML文档、CSS规则、JavaScript函数或代码块。用户明确要求HTML时，提示词可以保留该交付要求；没有要求时应根据需求选型，不默认单HTML。按作品集重新设计，不照搬课程、书册或历史问答。

每条核对：不是只有开场白；引用确实召回；输出完整结束；复制给其他模型后能实现要求。提示词通过不等于页面视觉验收通过。

本次本地修正了React Bits三条迁移后的规范地址，另将一条原有草稿的失效文档来源改为可访问的官方registry资料并保持draft。请替换云端01和04文档及系统提示词；仅改本地不会更新云端。本地生成接口还会在最终交付前校验提示词正文、简短说明与假设中已知来源网站的链接，要求与本轮实际采用案例的sourceUrl/implementationUrl一致，失败则保留需求并允许重试。直接在Coze聊天不会经过这层本地校验。

## 本地接口与已有Demo模块

Coze提示词与推荐请求使用流式响应：连续5分钟没有有效正文或思考进展时超时；有效进展会续期，普通心跳和状态帧不会续期；另有10分钟总上限。提示词入口不再附加5分钟绝对截止，避免正常输出到一半被中断。其他兼容模型提示词仍保持90秒，旧Demo显式指定的180秒调用预算不变。思考内容不展示，正式答案到达后继续增量显示；用户仍可停止，超时或连接中断保留输入与选择，并分别提示原因。流式改善显示和等待管理，不能保证上游服务一定成功，也不证明后台开启了哪种模型模式。

提示词请求携带设计规则、真实来源、效果机制和参数，不再附带整页HTML和组件源码。多轮修改保留全部用户要求与短对话，仅携带最近一份完整提示词作为修改基线，避免重复发送所有旧版本；浏览器里保存的历史记录不受影响。已确认案例全部保留，并优先提供匹配范例与视觉效果，额外检索案例最多6条。

强动效须围绕与用途相关的动态主体分工选材，功能控件不计入主视觉效果；普通手机保留简化后的持续主视觉。效果机制在模型正文中合并成一套可执行要求，服务端不再自动追加另一套本地实现方法；已确认对象、部位、保留项与真实来源仍由服务端补充，避免遗漏。规则改善不等于下游K3页面已完成视觉验收。

默认“生成提示词”已经走task=generate_prompt，流式解码developerPrompt并提供复制、下载和刷新恢复；程序包装还含message、referenceEntryIds、assumptions。“找参考”使用独立recommend协议。Coze直接聊天不需要显示JSON。

项目仍保留独立Demo生成/修改模块，它与提示词共用同一个Coze配置。**这份提示词角色不兼容旧Demo代码接口**，不要用该智能体测试“生成页面/应用页面修改”。本轮没有删除该模块或修改模型配置；以后若需站内生成代码，应接独立开发模型。参考库现有整页与组件预览仍可使用。

本地文件不会自动替换云端系统提示词、上传知识库或发布智能体。豆包实际效果要在完成云端配置后测试，不能由文档更新推定成功。
